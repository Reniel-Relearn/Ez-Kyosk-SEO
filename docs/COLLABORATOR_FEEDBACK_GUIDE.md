# Website design feedback guide

This guide explains how to review the EZ Kyosk website and leave useful feedback without editing any code.

## What you need

- The GitHub Pages review link.
- A free GitHub account.
- A desktop computer or phone with a modern browser.

## Review the website

1. Open the GitHub Pages review link supplied by the project owner.
2. Review both light and dark themes using the round theme button in the header.
3. Review the website on a computer and, if possible, on a phone.
4. Visit Home, Product, How It Works, Solutions, About, Contact, and Privacy.
5. Test navigation, buttons, product tabs, FAQ items, and the mobile menu.
6. Do not submit real confidential information through the review inquiry form.

## Leave feedback in GitHub

1. Sign in at `https://github.com`.
2. Open the EZ Kyosk repository: `https://github.com/Reniel-Relearn/Ez-Kyosk-SEO`.
3. Select the **Issues** tab near the top of the repository.
4. Open the issue titled **Website design review feedback**.
5. Scroll to the comment box at the bottom.
6. Copy the feedback format below into the box and replace each instruction with your answer.
7. Drag a screenshot into the comment box if it helps explain the concern.
8. Select **Comment** to submit the feedback.

## Feedback format

```text
Page or URL:
Section:
Device and browser:
Screen size, if known:
Theme: Light / Dark
What I noticed:
What I expected or recommend:
Priority: Critical / Important / Nice to have
Screenshot attached: Yes / No
```

## Example

```text
Page or URL: Home
Section: Payments
Device and browser: iPhone, Safari
Screen size, if known: iPhone 14
Theme: Dark
What I noticed: The payment card title feels too close to the image.
What I expected or recommend: Add a little more space between the title and image.
Priority: Nice to have
Screenshot attached: Yes
```

## Writing useful feedback

- Report one topic per comment when possible.
- Describe the observed problem before proposing a solution.
- Identify the exact page and section.
- Include the device, browser, and theme because layouts can differ.
- Use **Critical** only when content is inaccessible, misleading, broken, or blocks an important action.
- Do not post passwords, customer records, private contact details, payment information, or other confidential material.

## What happens after commenting

The project owner reviews the comment, asks follow-up questions if needed, and decides whether it is accepted, deferred, or declined. Accepted changes are implemented and published in a later review deployment.
